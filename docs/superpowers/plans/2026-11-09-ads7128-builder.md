# ADS7128 builder integration plan

**Goal:** Remove the standalone ADC diagnostic and make ADS7128 selectable in the normal hardware builder without changing existing profiles.

**Architecture:** Extend the device catalog, compiler's I2C validation, and editor address choices. Instantiate configured ADS7128 devices in a separate runtime map using the existing driver; keep the four-channel ADS1015 telemetry roles unchanged.

**Tech stack:** Python hardware compiler, browser JavaScript, Rust runtime, Nix/MixOS.

- [x] Confirm user wants a selectable extra device with current profiles unchanged.
- [x] Remove dedicated diagnostic source, early CLI dispatch, machine configuration, and active diagnostic documentation.
- [x] Add failing compiler and runtime tests, then implement catalog/editor/compiler and runtime initialization support.
- [x] Validate address ranges, bus activation, duplicate addresses, disabled devices, and preservation of existing roles and profiles.
- [x] Evaluate both normal machines and provide SD build commands for the user; leave image rebuilding and physical tests to the user.
- [x] Document the selectable-device boundary and provide editor/build/board-check commands.

The earlier integration and boot-test plans are historical records; this plan supersedes their standalone diagnostic steps. No voltage calibration, telemetry expansion, or default profile replacement is included.

Validation: 42 Python hardware/server/telemetry tests ran (one PostgreSQL-dependent skip), 19 pinmux tests passed, and seven native Rust hardware tests passed for each vehicle feature. Actual editor add/edit handlers passed a DOM-harness check for both ADC types. Normal Hybrid, debug, and Liquid SD derivations evaluate, and an assertion confirms the diagnostic machine is absent. Default profile files have no diff. Full SD images from the earlier integration are stale for this change; rebuild before testing.

Build-time compiler regressions now load immutable baseline profiles from `hardware/fixtures/profiles`, while a separate test compiles the actual saved profiles. Reproduced failing tests with a valid added ADS7128 in a temporary saved profile before this fix; the same edited-profile test run passes afterward. This lets editor saves change the device list without breaking fixed baseline assertions.

Both normal Nix `pinmuxOverlay` builds passed, including their packaged Python checks. Full SD images were not rebuilt in this follow-up; the user requested build/test commands to run next.
